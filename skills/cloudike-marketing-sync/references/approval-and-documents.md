# 사전 승인과 문서 최신화

## 모드별 범위
권한 확인 결과가 `local_only`이면 로컬 생성 대상과 검수 범위만 승인받는다. Drive 폴더·파일 ID와 원격 게시 방식 선택은 요구하지 않는다. 아래 Drive 반영·홈페이지 게시·PR 제출 승인 단계는 `publish_capable`에만 적용한다. 로컬 전용 모드에서도 문서 제작 사전 승인은 유지한다.

## 승인안 형식
제작 전에 아래 열을 갖춘 표를 사용자에게 제시한다.

| 대상 파일·링크 | 현재 페이지/슬라이드·섹션 | 작업 유형 | 기존 내용 | 제안 내용 | 예상 결과 위치 |
|---|---|---|---|---|---|

승인안에 change_id와 근거 PR 링크/커밋을 함께 적는다. 홈페이지 전체 변경을 서비스 소개서 PPTX와 그 파생 PDF에 대조하고, 각 문서에 대해 추가·변경·삭제 또는 영향 없음을 판단한다. 영향 없는 문서는 이유를 명시하고 불필요하게 수정하지 않는다. 기존 파일을 실제로 읽어 위치를 확인한다. 신규 문서에는 제안 페이지 번호와 제목·본문 요지를 모두 제시한다. 추가 페이지로 번호가 이동하면 현재 위치와 예상 위치를 구분한다. PDF는 PPTX의 어떤 페이지 변경으로 재출력되는지 명시한다. Drive의 대상 폴더와 기존 파일 ID 또는 새 생성 여부를 포함한다. 같은 문구가 여러 곳에 있으면 관련된 모든 위치를 열거한다.

영상도 별도 행으로 업그레이드된 앱 URL·대상 커밋·실제 조작할 기능·길이·장면·내레이션·프로젝트 로컬 저장 경로를 제시한다. 영상의 Drive 업로드는 승인안에 포함하지 않는다. 홈페이지 게시 범위는 PPTX·PDF의 수정 파일·연결 위치·게시 방식(직접 반영 또는 PR)을 명시하고 영상은 제외한다. 승인 전에는 문서·완성 영상의 초안도 생성하지 않고 텍스트 변경안으로 검토받는다. 사용자가 마케팅 팀 승인 역할을 수행할 수 있다. 별도 사람에게 메시지를 보내지는 않는다.

## PPTX와 PDF
문서 산출물은 서비스 소개서 PPTX 1개와 같은 최종본에서 출력한 PDF 1개, 총 2개로 한정한다. 홈페이지용·앱 기능소개용 별도 문서를 만들지 않는다. 홈페이지 소개자료 링크와 승인된 Drive 사본은 이 두 파일을 재사용한다. 과거 관리 문서 목록을 이유로 추가 문서를 생성하거나 수정하지 않는다.

기존 소개서는 지정 경로/연결된 Drive에서 찾고 파일 ID로 연결한다. 후보가 여럿이면 임의로 덮어쓰지 않고 대상 선택을 받는다. 없으면 새 소개서를 제안한다. 기본 구성은 서비스 개요, 주요 기능, 요금제, 문의 안내이며 장수는 근거와 승인안에 맞춘다.

문서 제작의 필수 의존성은 최신 `artifact-template-msaschool-purple`이다. 메인 지침의 버전 확인 절차를 거쳐 실제 참조 자산·서체·레이아웃을 사용하고, 제안서·매뉴얼·설명서·소개서 중 현재 문서 유형에 해당하는 작성·검수 규격을 적용한다. 화면 번호와 상세 설명의 대응, 글자 크기, 동일 페이지 배치 등의 구체적인 값과 배치 규칙은 이 파일에 중복 정의하지 않고 해당 스킬의 최신 규격을 기준으로 한다. 고객 브랜드는 Cloudike로 유지하고 참조 자료의 고객명·사례·교육 브랜드·수치를 복사하지 않는다. 기존 자료는 승인 범위의 콘텐츠를 수정하고 템플릿 스타일을 유지한다. 스타일 전환이 필요하면 그 범위도 승인안에 포함한다.

Cloudike 브랜드 표시는 스킬의 `assets/cloudike-logo.png`를 사용한다. 공식 홈페이지 헤더에서 추출한 283×54 PNG의 가로세로 비율을 유지하며 표지·본문의 공간과 해상도에 맞춰 배치한다. 기존 문서의 텍스트 브랜드를 로고 이미지로 교체하는 경우도 대상 페이지와 위치를 승인안에 포함한다. 이미지 출처는 `assets/cloudike-logo-source.json`을 참조한다.

실제 최신 홈페이지 캡처를 큰 화면 중심으로 배치하고 문구·요금표·수치는 편집 가능하게 유지한다. 전체 페이지를 단일 이미지로 만들지 않는다. 추가 기능은 관련 섹션에 삽입하고 변경 건은 기존 개체·화면을 교체한다. 반복 언급과 오래된 캡처도 함께 찾아 승인 범위 내에서 갱신한다.

최종 PPTX 전체 페이지를 렌더링해 잘림·겹침·누락과 수치 일치를 검사한다. 같은 최종 PPTX에서 PDF를 출력하고 페이지를 확인한다. Lab에서는 Standard 200GB·50GB 일치, Standard의 이전 100GB·25GB 잔존 여부, 타 플랜·가격 보존을 검사한다. 타 플랜의 정당한 100GB·25GB를 전역 치환하지 않는다.

## 문서 완료 후 담당자 확인과 영상 착수
서비스 소개서 PPTX 1개와 같은 최종본의 PDF 1개를 완성·검수한 뒤 담당자에게 두 파일의 링크, 페이지 수, 주요 변경과 검수 결과를 보여 준다. 담당자는 이 대화의 사용자가 맡을 수 있다. 담당자가 완성 문서를 명시적으로 확인한 다음 영상 녹화·편집·ElevenLabs 합성을 시작한다. 최초 제작 승인, 무응답, 시간 경과 또는 PR 제출 승인만으로 문서 확인을 갈음하지 않는다. 수정 요청이 있으면 반영·재검수한 두 파일을 다시 보여 주고 확인받는다.

확인 후에는 이미 제시한 영상 범위대로 제작을 이어가며 같은 범위에 중복 승인을 요구하지 않는다. 최종 MP4와 제작 원본은 프로젝트 `outputs/cloudike-marketing-sync/videos/<change_id>/`에 저장하고 실제 재생·청취 검수 결과와 파일 링크를 보고한다. 이 순서는 게시 가능·로컬 전용 모드 모두 적용한다. 홈페이지 소개자료에는 문서 PDF를 직접 연결하며 영상은 Drive나 홈페이지에 게시하지 않는다. PR 제출 승인은 문서 확인과 별개로 아래 절차를 따른다.

## 문서 완료 안내와 PR 제출 승인
이 절차는 `publish_capable` 모드에만 적용한다. `local_only`는 완성본 안내 후 PR 질문 없이 종료한다. 마케팅 팀의 사전 승인은 문서 제작 승인이다. PR 제출은 문서 생성·검수 후 완성본을 보여주고 별도로 확인받는다. 제작 전에 받은 포괄적인 PR 진행 승인도 이 완료 후 확인 단계를 대신하지 않는다.

1. 승인된 PPTX·PDF 제작과 검수를 마치고, 홈페이지 링크 변경 및 PR 제목·본문을 로컬에서 검토 가능한 상태로 준비한다. 승인된 문서 Drive 업로드는 기존 범위대로 진행할 수 있다.
2. 사용자에게 문서 생성 완료를 알리고 PPTX·PDF 경로 또는 링크, 페이지 수, 주요 변경 위치, 검수 결과와 미완료 사항을 제시한다. PR 대상 저장소·기준/작업 브랜치·변경 파일 목록·제안 제목도 함께 보여준다. 미완료 문서를 완료됐다고 안내하지 않는다.
3. “완성된 문서와 홈페이지 링크 변경을 위 내용으로 PR 제출할까요?”라고 질문하고 명시적 답변을 기다린다. 이 확인 전에는 PR용 원격 푸시 및 PR 생성·기존 PR 갱신을 진행하지 않는다. 무응답이나 경과 시간은 승인이 아니다.
4. 완료 안내 후 사용자가 승인하면 승인된 결과물로 커밋·푸시하고 PR을 제출한다. 같은 완성본의 재시도에는 승인 기록을 재사용한다. 이후 문서 내용이나 PR 범위가 바뀌면 수정본을 보여주고 다시 확인받는다. 병합은 사용자가 수행하도록 요청한 경우 사용자에게 남긴다.

## 홈페이지 다운로드 링크와 배포 검증
소개자료를 홈페이지에 게시하는 실행에서 적용한다. 승인안에 다운로드 대상 파일과 홈페이지 연결 위치·수정 범위·게시 방식을 포함한다. `리소스/자료실 → 필수 검토 자료 → 소개자료` 카드에 연결하는 요청은 별도의 자료실 페이지에 다운로드 버튼을 추가하는 것만으로 충족되지 않는다.

- 메인 HTML뿐 아니라 저장소 전체의 공통 메뉴·템플릿·복제된 HTML을 검색한다. 요금제·기능 소개·블로그 등 다른 경로에서도 같은 메뉴를 제공할 수 있다. 기존 링크 주소와 소개자료 메뉴의 실제 앵커를 함께 찾아 변경 대상을 열거한다. sparse checkout을 사용 중이면 작업 폴더 검색만으로 전체 검사를 대신하지 말고 Git 트리의 HTML·템플릿도 확인한다.
- 승인된 소개자료 링크는 동일한 최신 PDF를 직접 가리키고 다운로드할 수 있게 한다. 연결 대상은 위에서 생성한 서비스 소개서 PDF 1개다. 기존 `/cloudikehome/docs/cloudike-app-features.pdf` 경로를 유지한다면 해당 파일을 같은 최종 서비스 소개서 PDF로 갱신한다. 기존 경로명 때문에 별도 앱 기능소개서를 생성하지 않는다. 승인된 경로로 바꾸는 경우에도 모든 소개자료 메뉴·카드를 동일한 PDF에 연결한다. 실제 관리 파일 경로를 우선하고 `/cloudikehome/` 하위 경로와 중첩 페이지에서도 주소가 올바른지 확인한다. 기존 `https://cloudike.channel.io/workflows/705563`은 상담 정보 입력 폼이므로 PDF 다운로드 대상으로 유지하지 않는다. 다른 용도의 문의·상담 링크는 변경하지 않는다.
- 소개자료 카드가 빈 오버레이 앵커로 구현되어 있을 수 있으므로 표시 문구뿐 아니라 클릭 영역의 `href`와 `download` 속성을 확인한다. 본문·레이아웃·인코딩·개행을 보존하여 관련 링크만 수정한다.
- 변경 후 전체 대상에서 교체해야 할 이전 링크가 남아 있지 않은지 검사한다. 메인과 중첩 페이지(예: 요금제)의 실제 메뉴에서 파일을 다운로드하여 PDF 내용·페이지 수 또는 해시가 최종본과 일치하는지 확인한다. 브라우저가 상담 폼을 여는 상태를 다운로드 성공으로 처리하지 않는다.
- Git 반영 전 diff로 링크 외의 변경이 없는지 확인한다. 커밋 SHA·푸시 브랜치·PR URL·병합 여부·배포 확인 결과를 각각 보고한다. PR만 생성했다면 병합 대기로 기록하고 홈페이지 반영 완료라고 말하지 않는다. 병합 후에는 공개 홈페이지의 메인과 중첩 페이지에서 다시 다운로드를 확인해야 배포 검증 완료다. 배포 전 로컬 검증 결과와 공개 사이트 검증 결과를 구분한다.

## Google Drive
Drive 작업에는 연결된 google-drive 및 관련 스킬을 사용한다. 승인된 폴더에 PPTX·PDF만 업로드하고 ID를 저장한다. 최종 MP4와 영상 제작 원본은 프로젝트 로컬에만 보관한다. 다음 실행에는 이름 검색보다 저장한 ID를 우선하며 기존 파일의 새 버전으로 업데이트한다. 동일 이름의 새 파일을 반복 생성하지 않는다.

기존 대상이 Google Slides 등 네이티브 문서라면 형식을 확인하고 해당 도구로 직접 수정하는 계획을 승인받는다. 네이티브 파일에 PPTX 바이트를 덮어쓰지 않는다. 기존 ID 갱신이 도구에서 불가능하면 실패/대안을 보고하고, 승인 없이 중복 파일을 만들거나 기존 파일을 삭제하지 않는다. 삭제된 대상의 재생성은 변경안에 명시한다. 업로드 후 문서의 대상 ID·수정 시각·내용을 재확인한다. Drive 접근 실패를 파일 없음으로 처리하지 않는다. 원본 녹화·음성 원본·대본 등 제작 중간 자료는 프로젝트 로컬에 보관하며 별도 요청 없이 Drive에 올리지 않는다.

## PR 변경과 전체 결과물의 추적
새 기능·콘텐츠는 적절한 위치에 추가하고 기존 항목 변경은 기존 콘텐츠를 갱신한다. 삭제·폐지된 내용은 삭제 또는 종료 안내로 반영하는 안을 승인받는다. 기능 설명뿐 아니라 보안·정책·문의·사례·화면·링크 변경도 같은 원칙을 적용한다. PR에 없는 제품 주장은 만들지 않는다.

검수 시 각 change_id가 승인된 모든 대상 문서·페이지에 반영됐는지 역으로 대조한다. PPTX, 파생 PDF, Drive의 관리 소개서에 오래된 설명·표·이미지·링크가 남지 않았는지 확인한다. 이후 새로 생성하는 문서도 승인된 최신 콘텐츠 스냅샷과 변경 영향표를 사용하며 과거 템플릿 문구로 되돌아가지 않는다. 영상의 관련 화면·대본·자막도 같은 변경을 반영한다. 요금제 검사는 Lab 예시이며 일반 실행의 검수 범위를 제한하지 않는다.
