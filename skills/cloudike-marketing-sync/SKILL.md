# 클라우다이크 마케팅 자료 최신화

## 기본 대상과 재사용
- 홈페이지: https://acmexii.github.io/cloudikehome/
- 앱 기본 URL: https://acmexii.github.io/cloudikehome/app/ . 영상은 승인된 Git 변경이 배포된 실제 앱을 직접 조작하며 녹화한다. 변경된 앱의 배포 URL이 따로 지정되면 해당 URL을 사용한다. 홈페이지에는 PPTX·PDF를 연결하고, 최종 영상은 프로젝트 로컬에만 보관하며 Drive에 업로드하지 않는다.
- 공식 브랜드 로고: [assets/cloudike-logo.png](assets/cloudike-logo.png). `https://cloudike.kr/`의 헤더에서 추출한 원본이며, 출처·확인일·크기·해시는 [출처 기록](assets/cloudike-logo-source.json)에 보관한다. 소개서 표지·본문 브랜드 영역 및 영상의 필요한 브랜드 표시에 이 자산을 재사용한다. 원본 비율·색·투명도를 유지하고 작은 원본을 과도하게 확대하지 않는다. 텍스트로 로고를 재현하거나 템플릿의 MSASchool·유엔진 로고를 Cloudike 로고 대신 쓰지 않는다. 공식 로고 변경이 확인되면 새 자산과 교체 범위를 사전 승인안에 포함한다.
- 저장소: https://github.com/acmexii/cloudikehome , 기준 브랜치 `main`. PR URL은 선택 입력이며, 저장소에서 대상 커밋에 연결된 PR을 자동 조회한다.
- 작업공간의 `outputs/cloudike-marketing-sync/`에 실행 상태와 결과물을 관리한다. 최초에 기존 소개서를 검색하고 관리 대상을 연결한다. Drive 폴더가 미지정이면 연결된 도구로 후보를 확인하고 모호한 경우 선택받는다.
- 문서 생성·수정 시마다 최신 `artifact-template-msaschool-purple` 스킬을 반드시 적용한다. `skill-slide-msaschool`은 배포 저장소 이름이며 실제 스킬 이름은 `artifact-template-msaschool-purple`이다. 제작 전 설치본과 배포 저장소 `https://github.com/acmexii/skill-slide-msaschool`의 현재 버전을 비교하고, 최신 `SKILL.md`, 디자인 규격·레이아웃 지도와 해당 문서 유형의 참조 이미지를 읽는다. 과거 실행의 지침·생성 스크립트·기억만으로 제작하지 않는다. 설치본이 오래됐으면 최신 지침·자산을 확인해 사용하되 로컬 수정은 자동 덮어쓰기하지 않는다. 스킬 누락·접근 실패로 최신 규격을 확인할 수 없으면 해당 문서 제작을 보류하고 원인을 알린다. 임의의 보라색 템플릿으로 대체하지 않는다. PPTX/PDF 실제 제작에는 Presentations 및 PDF 스킬의 검수 절차를 적용한다.
- 영상 제작에는 형제 스킬 [cloudike-service-video](../cloudike-service-video/SKILL.md), [마우스 연출](../cloudike-service-video/references/interaction-motion.md), [ElevenLabs 설정](../cloudike-service-video/references/elevenlabs.md)을 읽고 재사용한다. 이 스킬에서는 대상 URL과 길이 20~40초를 우선한다. API·녹화 도구 지원은 실행 환경에서 확인한다.

## 필수 실행 순서
1. **Git 게이트:** 최초에는 현재 main 커밋을 최초 처리 대상으로 삼는다. 이후에는 마지막 완료 커밋 이후 홈페이지 전체 콘텐츠의 변경과 연결된 PR의 Diff를 확인한다. 미병합 PR은 분석만 하고 제작·게시 대상으로 확정하지 않는다. 새 관련 커밋 또는 실제 홈페이지 콘텐츠 변경이 없으면 사용자에게 정확히 `변경 된 사항이 없습니다.`라고 알리고 즉시 종료한다. 승인안 작성·캡처·녹화·문서 생성/수정·TTS·Drive 업로드·홈페이지 게시를 진행하지 않는다. 미완료 실행이 있어도 일반 실행에서는 자동 재개하지 않는다. 사용자가 미완료 작업 재개를 명시적으로 요청한 경우에만 기존 승인 범위에서 재개한다. 상세 판단과 상태는 [Git과 실행 상태](references/source-and-state.md)를 따른다.
2. **변경안 준비:** 승인 전에는 Git·기존 소개서·Drive 파일을 읽고, 홈페이지를 열어 배포 여부와 반영 위치를 확인할 수 있다. 결과물 생성·기존 문서 수정·Drive 쓰기·영상 녹화·유료 합성·게시를 시작하지 않는다. [사전 승인안](references/approval-and-documents.md)의 표를 작성한다.
3. **마케팅 팀 명시적 승인:** 대상 문서 목록, 페이지/슬라이드·섹션, 변경/추가 구분, 기존 내용과 반영 내용, 영상 및 게시 범위를 제시하고 기다린다. 무응답·경과 시간·스킬 호출 자체는 승인이 아니다. 최초 생성도 페이지별 구성 승인이 필요하다. 일부 승인 시 승인된 범위만 진행한다. 승인 후 대상 커밋이나 내용이 달라지면 다시 승인받는다.
4. **실제 화면 확보와 제작:** 승인된 커밋의 정보가 홈페이지와 대상 앱에 실제 배포됐는지 검증한다. 이전 값이면 배포 대기로 기록하고 쓰기를 중단한다. 문서용 화면을 직접 탐색·캡처하고, 영상은 업그레이드된 실제 앱의 해당 기능을 조작하며 화면 반응과 결과까지 녹화한다. 정적 사본에 변경 기능이나 실제 반응이 없으면 해당 영상 제작을 보류하고 동작하는 배포 앱이 필요함을 알린다. [문서 처리](references/approval-and-documents.md), [영상 처리](references/video-production.md)를 수행한다.
5. **반영과 검수:** PPTX를 렌더링해 검수하고 같은 최종본에서 PDF를 출력한다. Drive에는 PPTX·PDF만 생성하거나 기존 ID에 새 버전으로 반영한다. 최종 MP4와 제작 원본은 프로젝트 로컬에만 보관하고 영상은 Drive에 업로드하거나 홈페이지에 게시하지 않는다. 홈페이지에는 PPTX·PDF를 연결하며 [다운로드 링크와 배포 검증](references/approval-and-documents.md#홈페이지-다운로드-링크와-배포-검증)에 따라 전체 페이지의 복제 메뉴와 실제 다운로드를 검증한다. 승인된 게시 방식에 맞춰 저장소에 문서를 반영하고 배포 결과를 확인한다. 커밋·푸시·PR 생성·병합·배포 완료를 구분하며 GitHub Pages를 로컬 파일 복사만으로 배포 완료라고 보고하지 않는다.
6. **결과 보고와 상태 기록:** 결과물 링크, 반영 커밋, 변경 위치, 검수 결과, 미완료 작업을 보고한다. 결과물별 성공을 기록하고 필수 단계가 모두 성공한 경우에만 완료 기준을 이동한다. 실패하면 성공한 단계를 중복 실행하지 않고 승인 범위 안에서 재개한다.

## 콘텐츠 원칙
추가 기능은 기존 문서 흐름의 적절한 위치에 추가하고 삽입 위치를 승인받는다. 변경 기능은 기존 문구·표·캡처를 갱신하며 중복 페이지를 무조건 추가하지 않는다. 변경 범위는 요금제에 한정하지 않는다. 기능·서비스 설명·활용 사례·지원 환경·보안·정책·문의·이미지·화면·링크 등 홈페이지 전체 콘텐츠가 대상이다. PR에서 확인한 각 변경을 관리 중인 모든 문서의 관련 위치에 연결한다. PR에서 변경되지 않은 가격·타 플랜·근거 없는 효익을 임의로 바꾸지 않는다. 요금제 Lab의 예시는 Standard 기본 용량 100GB→200GB, 무료 백업 25GB→50GB다. 실제 값은 Git과 배포 화면으로 확인하며 예시를 제품 사양으로 하드코딩하지 않는다.

## 스킬 생성과 실사용 구분
스킬 작성·검증 요청만으로 홈페이지 수정, 커밋·푸시, Drive 업로드, 유료 TTS 또는 영상 제작을 실행하지 않는다. 실제 최신화 시에는 위 사전 승인 단계가 반드시 적용된다. 키·토큰·DPAPI 파일은 결과물·상태 파일·저장소에 넣지 않는다.
